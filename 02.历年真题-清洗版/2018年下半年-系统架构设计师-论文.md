## 试题一：论软件开发过程 RUP 及其应用

RUP（Rational Unified Process）是 IBM 公司的一款软件开发过程产品。它提出了一整套以 UML 为基础的开发准则，用以指导软件开发人员进行软件开发。RUP 汲取了各种面向对象分析与设计方法的精华，提供了一个通用的软件过程框架，可以适应不同的软件系统、应用领域、组织类型和项目规模。

请围绕“论软件开发过程 RUP 及其应用”论题，依次从以下三个方面进行论述。

### 写作要求

1. 概要叙述你参与管理和开发的软件项目，以及你在其中所担任的主要工作。
2. 详细论述软件开发过程产品 RUP 所包含的 4 个阶段以及 RUP 的基本特征。
3. 结合你参与管理和开发的软件项目，详细阐述 RUP 在该项目中的具体实施内容，包括核心工作流的选择、制品的确定、各阶段之间的演进及迭代计划，以及工作流内部结构的规划等。

### 备考提示（非官方）

> 以下内容沿用底稿中的解析，仅供备考梳理，不是官方答案或范文。

#### 对应要求一

简单介绍所参与软件开发项目的背景及主要内容，并说明在其中所担任的主要工作。

#### 对应要求二

RUP 的 4 个阶段包括：

1. **初始阶段：** 定义最终产品视图和业务模型，并确定系统范围。
2. **细化阶段：** 设计并确定系统的体系结构，制定工作计划及资源要求。
3. **构造阶段：** 构造产品，并继续演进需求、体系结构和计划，直至产品提交。
4. **移交阶段：** 将产品提交给用户使用。

RUP 的基本特征包括：

1. **受控的迭代式增量开发：** 将软件开发分为一系列小的迭代过程，在每次迭代中逐步增加信息并进行细化；根据具体情况决定迭代次数、每次迭代的持续时间和迭代工作流；每次迭代选择当前对风险影响最大的用例，以分解和降低风险。
2. **用例驱动：** 用用例捕获目标系统的功能需求；用用例驱动软件的整个开发过程，保证需求可追踪，确保系统功能得到实现；将用户关心的业务功能模型与开发人员关心的功能实体模型结合起来，提供贯穿软件生命周期的开发方法，使各阶段工作自然、一致地协调。
3. **以软件体系结构为中心：** 强调在开发早期识别与软件体系结构密切相关的用例，通过这些用例的分析、设计、实现和测试形成体系结构框架；在后续阶段不断细化已有的体系结构框架，最终实现整个系统；开发早期形成良好的软件体系结构，有利于理解系统、支持重用并有效组织软件开发。

#### 对应要求三

结合具体项目，从以下五个方面说明 RUP 的具体实施内容：

1. 确定本项目的软件开发过程需要哪些工作流。RUP 的 9 个核心工作流并非总是全部需要，可以根据项目规模、类型等进行取舍。
2. 确定每个工作流需要产出哪些制品。
3. 确定 4 个阶段之间如何演进。以风险控制为原则，决定每个阶段执行哪些工作流、各工作流执行到什么程度、产出哪些制品，以及每项制品完成到什么程度等。
4. 确定每个阶段内的迭代计划，规划 RUP 的 4 个阶段中每次迭代开发的内容。
5. 规划工作流内部结构。工作流不是活动的简单堆积，它涉及角色、活动和制品；其复杂程度与项目规模和角色数量等有很大关系，内部结构通常用活动图表示。

## 试题二：论软件体系结构的演化

软件体系结构的演化，是在构件开发过程中或软件开发完毕并投入运行后，由于用户需求发生变化而相应修改原有软件体系结构，以满足新需求的过程。体系结构演化是一个复杂且难以管理的问题。

请围绕“论软件体系结构的演化”论题，依次从以下三个方面进行论述。

### 写作要求

1. 概要叙述你参与管理和开发的软件项目，以及你在其中所承担的主要工作。
2. 软件体系结构演化通过系统演化步骤修改系统，以满足新的需求。简要论述系统演化的 6 个步骤。
3. 具体阐述你参与管理和开发的项目如何基于系统演化的 6 个步骤完成软件体系结构演化。

### 备考提示（非官方）

> 以下内容沿用底稿中的解析，仅供备考梳理，不是官方答案或范文。

#### 对应要求一

结合自己参与的信息系统项目，说明在其中所承担的工作。

#### 对应要求二

此处的“软件体系结构演化”指 ABSD 方法中的最后一个阶段。体系结构演化使用系统演化步骤修改应用，以满足新的需求，主要包括以下六个步骤：

1. **需求变动归类：** 对用户需求的变化进行归类，使变化的需求与已有构件对应。对找不到对应构件的变动做好标记，以便在后续工作中创建新构件来应对这部分需求。
2. **制订体系结构演化计划：** 在改变原有结构前，开发组织必须制订周密的体系结构演化计划，作为后续演化开发工作的指南。
3. **修改、增加或删除构件：** 根据需求变动归类结果，决定是否修改或删除已有构件，或增加新构件；最后对修改和增加的构件进行功能性测试。
4. **更新构件的相互作用：** 随着构件的增加、删除和修改，更新构件之间的控制流。
5. **构件组装与测试：** 通过组装支持工具将构件实现体组装起来，完成整个软件系统的连接与合成，形成新的体系结构；然后测试组装后系统的整体功能和性能。
6. **技术评审：** 确认上述步骤，评审组装后的体系结构是否反映需求变动并符合用户需求；若不符合，则在第 2 至第 6 步之间迭代。

#### 对应要求三

结合项目实际工作，阐述 6 个步骤的具体应用。可以重点讲述其中 2～3 个方面，不必平均展开，最后说明实施效果。

## 试题三：论面向服务架构设计及其应用

面向服务架构（Service-Oriented Architecture，SOA）是一种应用框架，将日常业务应用划分为单独的业务功能服务和流程，并通过定义良好的接口和标准协议将这些服务关联起来。通过实施基于 SOA 的系统架构，用户可以构建、部署和整合服务，而无须依赖具体应用程序及其运行平台，从而提高业务流程的灵活性，帮助企业加快发展速度、降低开发成本，并改善业务流程的组织和资产重用。

请围绕“论面向服务架构设计及其应用”论题，依次从以下三个方面进行论述。

### 写作要求

1. 概要叙述你参与分析和开发的软件系统开发项目，以及你所担任的主要工作。
2. 说明面向服务架构的主要技术和标准，详细阐述每种技术和标准的具体内容。
3. 详细说明你所参与的软件系统开发项目中，构建 SOA 架构时遇到了哪些问题，以及具体实施效果。

### 备考提示（非官方）

> 以下内容沿用底稿中的解析，仅供备考梳理，不是官方答案或范文。

#### 对应要求一

简要描述所参与分析和开发的软件系统开发项目，并明确指出在其中承担的主要任务和开展的主要工作。

#### 对应要求二

面向服务架构的主要技术和标准包括：

1. **UDDI（统一描述、发现和集成协议）：** 实现商业实体的发布、查找和发现机制，定义商业实体之间如何在网络上相互作用和共享信息。通过构建 UDDI 模块，商业实体能够快速、方便地使用自身的企业应用软件发现合适的商业对等实体，并与其开展电子化商业贸易。UDDI 包含服务描述与发现的标准规范。
2. **WSDL（Web 服务描述语言）：** 一种描述 Web 服务并说明如何与 Web 服务通信的 XML 语言，也是 Web 服务的接口定义语言。WSDL 可以描述服务所提供的操作、服务交互的数据格式和协议，以及协议地址等基本属性。它以端口集合的形式描述服务，包含对一组操作和消息的抽象定义、绑定这些操作和消息的具体协议，以及该绑定的网络端点规范。WSDL 分为服务接口描述和服务实现描述两种类型。
3. **SOAP（简单对象访问协议）：** 分散或分布式环境中基于 XML 的信息交换协议，主要包含四部分：SOAP 封装定义描述消息内容、发送方、接收方及处理方式的框架；SOAP 编码规则用于表示应用程序所需数据类型的实例；SOAP RPC 表示远程过程调用和应答的约定；SOAP 绑定用于通过底层协议交换信息。
4. **BPEL（业务流程执行语言）：** 面向 Web 服务的服务定义和执行过程描述语言。用户可以通过组合、编排和协调 Web 服务，自上而下地实现面向服务的体系结构。BPEL 提供了相对简单易懂的方法，可将多个 Web 服务按照业务流程组合成新的组合服务；新服务可以作为一个新的 Web 服务被访问，也可以继续组合成更大的服务。

#### 对应要求三

结合实际项目说明构建 SOA 架构时遇到的问题，并描述实施后的实际应用效果。底稿将主要问题分为三类：

1. SOA 系统如何与原有系统中的功能集成。
2. SOA 系统服务的设计及服务粒度的控制。
3. 无状态服务的设计及服务流程的组织。

## 试题四：论 NoSQL 数据库技术及其应用

随着互联网 Web 2.0 网站兴起，传统关系数据库在应对 Web 2.0 网站，特别是超大规模、高并发的纯动态 SNS 网站时已显得力不从心，暴露出许多难以克服的问题；非关系型数据库则因自身特点得到迅速发展。

NoSQL（Not Only SQL）的产生，是为了解决大规模数据集合及多种数据类型带来的挑战，尤其是大数据应用难题。目前 NoSQL 数据库没有统一架构，根据所采用的数据模型可分为四类：键值（Key-Value）存储数据库、列存储数据库、文档型数据库和图（Graph）数据库。

### 备考提示（非官方）

> 以下内容沿用底稿中的解析，仅供备考梳理，不是官方答案或范文。

#### 对应要求一

#### 对应要求二

常见的 NoSQL 数据库主要分为四类：

1. **键值（Key-Value）存储数据库：** 主要使用哈希表，表中有特定的键和指向特定数据的指针。Key-Value 模型的优势是简单、易部署；但当 DBA 只查询或更新部分值时，效率较低。例如 Tokyo Cabinet/Tyrant、Redis、Voldemort、Oracle BDB。
2. **列存储数据库：** 通常用于应对分布式存储的海量数据。键仍然存在，但会指向多个列，这些列由列族组织。例如 Cassandra、HBase、Riak。
3. **文档型数据库：** 数据模型是版本化文档，半结构化文档以特定格式存储，例如 JSON。文档型数据库可视为键值数据库的升级版，允许嵌套键值，且查询效率通常高于键值数据库。例如 CouchDB、MongoDB、SequoiaDB。
4. **图（Graph）数据库：** 使用图模型，并能扩展到多个服务器。NoSQL 数据库没有标准的查询语言，因此查询时需要根据具体数据模型进行操作。许多 NoSQL 数据库提供 REST 风格的数据接口或查询 API。例如 Neo4j、InfoGrid、InfiniteGraph。

NoSQL 数据库较适用于以下情况：

1. 数据模型较简单。
2. 需要灵活性更强的 IT 系统。
3. 对数据库性能要求较高。
4. 不需要高度的数据一致性。
5. 对于给定的键，容易映射复杂值。
