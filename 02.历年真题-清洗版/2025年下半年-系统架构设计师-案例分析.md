## 试题一：电动车充电管理系统架构评估（25 分）

### 说明

某新能源科技公司拟升级电动车充电管理系统，为用户提供智能化、高可靠性的充电服务。充电设备覆盖多个城市，用户规模快速增长，系统需兼顾性能、安全性与易用性。新系统除支持固定充电模式外，还需根据车辆型号、电量需求和充电时段动态调整策略，并在高峰时段分配充电资源。系统还需与第三方支付、地图导航、电力调度等平台集成。

需求和质量属性描述如下：

- （a）用户发起充电请求后，系统需在 3 秒内响应并分配可用充电口。
- （b）当充电站点周边 200 米内已有超过 80% 的充电口被占用时，系统自动限制新设备接入，并确保 CPU 使用率不超过 40%，不影响当前任务处理。
- （c）集成第三方支付平台的新 API 需在 3 个工作日内完成。
- （d）单点故障恢复时间不超过 5 分钟。
- （e）系统能够模拟雷电、下雨、冰雹等恶劣天气下的充电场景，测试设备防水、防雷和稳定性。
- （f）支持远程调用测试接口。
- （g）用户敏感信息采用 AES-256 加密存储与传输。
- （h）系统支持多语言和多种操作模式，方便残疾人使用。
- （i）运维人员能够在 2 小时内快速替换故障模块，无须开发人员介入。
- （j）用户首次使用系统时，应在 30 秒内完成核心功能引导。
- （k）系统适配不同分辨率的手机、平板和车载屏幕。
- （l）主站点网络中断时能够保存用户操作记录。
- （m）集成电力调度平台的新 API 需在 5 个工作日内完成联调与测试。
- （n）手机无网络时，系统进入安全模式，保存充电记录并在网络恢复后同步到云端，同时显示上次充电状态供用户核对。

系统架构师提出微服务架构和分布式集群架构两种方案，公司拟组织专家进行评估。

#### 问题3

互斥锁方案：

- 优点：同一时间只允许一个线程回源并更新缓存，可减少并发回源和脏数据风险；流程相对直观，易于理解和实现。
- 缺点：其他线程可能因等待锁而阻塞，降低响应速度和吞吐量；持锁线程异常且锁未正确过期或释放时可能导致死锁或长期不可用。

逻辑过期方案：

- 优点：缓存逻辑过期后仍可先返回旧数据，避免请求阻塞，通常具有较好的并发响应能力。
- 缺点：在更新完成前用户可能读到旧数据，只能保证最终一致性；需要维护逻辑过期时间和后台更新流程，实现更复杂；数据若不设置物理过期，需额外清理不再使用的缓存，避免长期占用内存。

### 参考答案（非官方）

> 以下内容来自底稿所附答案，非官方标准答案。

#### 问题1

1. **软硬件协同：** 统一调度 CPU、GPU、NPU 等异构算力，提高资源利用率与能效。
2. **轻量化：** 采用可裁剪、模块化设计以适应资源受限环境，并支持功耗管理。
3. **原生 AI 支持：** 集成模型推理相关能力，支持在本地低延迟执行，减少对云端的持续依赖并保护数据隐私。
4. **实时性与可靠性：** 面向工业控制、自动驾驶等场景提供可预测响应，并通过隔离机制提高稳定性。
5. **端云协同：** 协调本地实时处理与云端复杂计算，支持远程更新和模型优化。

#### 问题2

轻量级内核在底稿中也称微内核，其核心思想是只把最基础的功能保留在内核态，把其他服务作为相对独立的用户态进程运行。

底稿列出的特点包括：

- **内核精简：** 主要负责进程调度、进程间通信和基础内存管理等核心任务。
- **模块化与服务化：** 系统服务以独立进程存在，通过定义良好的通信机制协作，便于扩展、裁剪和更新。
- **安全性与可靠性：** 用户态服务拥有相对独立的地址空间，单个服务崩溃时可降低对内核和其他服务的影响。
- **实时响应：** 通过控制中断延迟和调度时间，为需要确定性响应的场景提供支持。
