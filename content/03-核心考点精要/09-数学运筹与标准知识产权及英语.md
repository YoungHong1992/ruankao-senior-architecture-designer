# 数学运筹与标准知识产权及英语

本篇为 AI 辅助整理的非官方学习手册。概念采用教材归纳与明确标出的工程补充；口诀、例题、答案及作答模板均为教学归纳，不是官方答案或真实项目事实。优先级是学习安排，样本考频不代表未来命题概率。

## 范围与优先级

优先级 P1。2023 年起仓库五场考试的主主题统计：综合知识 60 题、案例 0 道大题、论文 0 题。每题只归一个主主题；组内粒度不同，计数不代表单考点概率或预测分值。具体题号与分年结果见[样本记录](../../verification/核心考点精要-考频样本.md)，覆盖边界见[覆盖表](11-大纲与教材考点覆盖表.md)。

## 概率与排列组合

- 排列考虑顺序：A(n,m)=n!/(n-m)!；组合不考虑顺序：C(n,m)=n!/[m!(n-m)!]。
- P(A∪B)=P(A)+P(B)−P(A∩B)。互斥意味着交集为空；独立意味着 P(A∩B)=P(A)P(B)，两者不同。
- 条件概率 P(A|B)=P(A∩B)/P(B)，要求 P(B)>0。
- 若事件 B_i 构成划分，P(A)=ΣP(A|B_i)P(B_i)；贝叶斯公式用它作分母反推原因概率。
- 期望是各结果乘概率后求和，不代表每次都会出现该结果。

自编例题：供应商甲供货占 60%，乙占 40%，缺陷率分别为 1%、3%。随机发现一件缺陷品，其来自乙的概率为 0.4×0.03/(0.6×0.01+0.4×0.03)=2/3。不能直接回答 3%。

## 运筹与项目计算

| 题型 | 步骤 | 易错点 |
|---|---|---|
| 线性规划 | 定义变量→目标函数→约束→非负条件→求可行最优解 | 最优值必须同时满足所有约束 |
| 关键路径 | 正推最早时间，逆推最迟时间，找总时差为零的活动 | 可能有多条关键路径 |
| 决策树 | 从叶节点向前计算期望，比较备选方案 | 成本与收益符号一致 |
| 最短路径 | 比较源点到目标的路径代价 | 与连接全部节点的最小生成树不同 |
| 排队分析 | 明确到达率、服务率、队列和系统边界 | 只有稳定系统才能使用稳态结论 |

关键路径自编例题：A 用时 3，B、C 都在 A 后开始，分别用时 4、2；D 在 B、C 完成后开始，用时 2。路径 A-B-D 为 9，A-C-D 为 7，工期为 9，C 的总时差为 2。若 B 缩短 3，关键路径会切换，不能一直按原路径减工期。

活动时间公式：EF=ES+工期；某活动 ES 取前置活动 EF 最大值；LF 取后继活动 LS 最小值；LS=LF−工期；总时差=LS−ES。资源约束题还需单独考虑资源冲突。

PERT 教学公式：乐观 a、最可能 m、悲观 b，则估计期望工期 (a+4m+b)/6，方差 ((b−a)/6)²。必须看题目是否采用该估计模型，不能用它替代所有工期数据。

## 算法与复杂度速查

二分查找需要有序且可有效定位中间元素；常见数组实现比较次数为 O(log n)。哈希平均查找可为 O(1)，依赖散列与负载等假设，最坏情况不能一概写 O(1)。归并排序典型时间 O(n log n)；快速排序平均 O(n log n)、最坏 O(n²)。

贪心每步选局部最优，需要证明选择性质；动态规划利用重叠子问题和最优子结构；分治将问题拆成子问题再合并。题目要求最优解时，不能仅凭“每次选最快”断言贪心正确。

## 标准与知识产权

以下为规则辨析教学摘要，核对日期为 2026-10-11；涉及版本时以题设年份和适用规则为准，不能把旧题的历史答案直接当作现行规定。

国家标准有强制性与推荐性之分；行业标准、地方标准属于推荐性标准。还要区分团体标准、企业标准。GB/T 中的 T 表示推荐性，不能把“标准”一词一律等同于强制执行。依据：[市场监管总局《标准化法》第二条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_d7040b9f1d0f4980a0e55089a57bf37d.html)。

专利题先区分发明、实用新型和外观设计。依《专利法》第四十二条，一般期限分别为 20、10、15 年，均从申请日起计算；还须注意法定期限补偿等特别规定。旧资料中的“外观设计 10 年”不能直接套入现行规则。发明、实用新型的授权条件关注新颖性、创造性、实用性。依据：[国家知识产权局《专利法》](https://www.cnipa.gov.cn/art/2020/11/23/art_2197_155169.html)。

做权属题按四步读题：识别权利种类；识别创作或开发主体；查职务、委托、合作及合同约定；最后判断授权行为与期限。著作权、专利权、商标权不是同一种保护机制，不宜套同一归属或年限口诀。具体软件著作权期限、职务开发和许可例外须回查对应法规，本篇不将其简化成统一数字。

工程补充：开源不等于没有许可条件；使用、修改、再分发、提供网络服务可能触发不同许可条款。答题应围绕给定许可文本，不能只凭“免费”判断合法使用范围。

## 专业英语：按概念和句法解题

| 英语 | 含义 | 区分对象 |
|---|---|---|
| availability / reliability | 可用性 / 可靠性 | 正常服务占比与无故障运行能力 |
| scalability / extensibility | 可伸缩性 / 可扩展性 | 容量扩展与功能扩展，结合上下文 |
| throughput / latency | 吞吐量 / 时延 | 单位时间完成量与单次耗时 |
| consistency / durability | 一致性 / 持久性 | 状态约束与提交后保存 |
| coupling / cohesion | 耦合 / 内聚 | 模块之间与模块内部 |
| authentication / authorization | 身份认证 / 授权 | 是谁与允许做什么 |
| constraint / trade-off | 约束 / 权衡 | 限制条件与得失平衡 |
| fault tolerance / recovery | 容错 / 恢复 | 带故障继续服务与恢复状态 |

步骤：先找主谓和指代对象，再看转折、因果、比较与否定，最后用领域知识检查选项。unless、rather than、whereas 等词会改变逻辑，不能只找熟悉名词。

自编句子：Replication improves availability, but asynchronous replication may expose stale reads. 含义是复制可以改善可用性，但异步复制可能读到旧值；不能翻译成“复制保证实时一致”。

## 补强：组合计数、资源约束与软件权利

自编组合例：0～999 恰有一个数字 5。统一看成允许前导零的三位数，选择 5 的位置有 3 种，其余位置各有 9 种非 5 选择，结果为 3×9²=243；1000 不含 5，所以扩展到 0～1000 仍是 243。关键是先说明前导零为何不影响所计数字。

三集合容斥：并集人数为单项人数之和−两两交集人数之和+三者交集人数；“都不会”用总人数减并集。两两交集通常包含三者都会的人，不能自行当作“恰好会两种”。

资源受限进度问题先算无资源约束的关键路径下界，再检查每个时间段的资源占用，给出可行排程并与下界比较。只有可行方案不能证明最短，还需要下界或穷举/优化证明。赶工题同时考虑直接费增加与间接费减少；存在多条关键路径时只压缩其中一条未必缩短总工期。

知识产权教学补充：软件保护覆盖程序及相关文档，不直接覆盖软件采用的思想或数学概念；著作权自开发完成产生，登记不是产生权利的前提。委托开发先看书面约定，未约定或不明确时按条例由受托人享有。自然人期限按终生及死亡后 50 年计算至相应年末，合作开发看最后死亡者；法人等按首次发表后 50 年至年末，另有开发完成后 50 年内未发表的限制。学习研究设计思想的法定使用情形不等于可任意再分发软件。回查：[国家版权局公开条例第 6、7、11、14、17 条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/200701/t20070109_50527.html)。该链接为 2001 年版本公开页；本段用于对应历史试题条文学习，现行适用及其他条款须另查修订文本，不能照搬该页旧处罚规定。

自编自测：约束最短工期为 9 天，但安排出现同一时段资源超额，能否答 9 天？答案：不能，9 只是该约束下的下界，需找到满足全部约束的方案。软件委托开发是否当然归出资方？答案：否，先查合同，再适用对应法定规则。

## 补强：标准生命周期、类别与机构

标准化通过共同规则减少协作和互操作中的歧义。学习其发展时，区分从产品与接口协调扩展到过程、管理和服务的范围变化；具体历史时间线应另查专题资料。

以 ISO 为例，标准制定包含提案、准备、委员会、征询、批准、出版阶段；委员会阶段可选，批准阶段也可按条件跳过，不能背成每个项目必经的固定六步。发布后还会经历复审，决定继续有效、修订或撤销。不要把软件开发生命周期与标准生命周期混同。参见 [ISO 制定阶段](https://www.iso.org/stages-and-resources-for-standards-development.html)及[阶段代码](https://www.iso.org/stage-codes.html)。

| 大纲类别 | 约束对象 | 学习时的辨析 |
|---|---|---|
| 代码标准 | 对信息对象的编码与表示规则 | 先辨明题干所指编码对象，不能一律理解成程序编码风格 |
| 文件格式标准 | 文件结构、字段与交换表示 | 扩展名相同不保证内部格式或版本兼容 |
| 安全标准 | 安全目标、控制要求与评价依据 | 要区分管理要求、产品要求和评价方法 |
| 软件开发规范 | 开发活动、过程及产物要求 | 过程符合要求不自动证明产品没有缺陷 |
| 文档标准 | 文档类别、内容组织与表达要求 | 文档齐全不等于内容正确，也不等于代码满足需求 |

上述表格是按大纲类别编写的理解提示；具体标准编号、版本、适用范围和条款仍需逐项回查，不能用类别说明替代标准原文。

机构侧先记三类职责：[ISO](https://www.iso.org/about)通过成员和技术委员会协作制定国际标准；[IEC](https://www.iso.org/files/live/sites/isoorg/files/store/en/PUB100437.pdf)侧重电工、电子及相关技术；[ITU](https://www.itu.int/en/about/Pages/default.aspx)承担信息通信领域的国际协作，包括标准化工作。技术委员会负责具体领域工作，不应与标准发布机构混为一谈。其他国际、国家和行业机构的完整职责仍需回查。

自测：标准发布后是否永久有效？答案：否，应关注复审、修订和撤销状态。标识同一标准时为什么要看年代号？答案：不同版本的要求和适用条件可能不同。
