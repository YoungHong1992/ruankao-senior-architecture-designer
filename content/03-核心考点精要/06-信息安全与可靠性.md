# 信息安全与可靠性

本篇为 AI 辅助整理的非官方学习手册。概念采用教材归纳与明确标出的工程补充；口诀、例题、答案及作答模板均为教学归纳，不是官方答案或真实项目事实。优先级是学习安排，样本考频不代表未来命题概率。

## 学习范围与优先级

优先级 P0。2023 年起仓库五场考试的主主题统计：综合知识 28 题、案例 1 道大题、论文 1 题。每题只归一个主主题；组内粒度不同，计数不代表单考点概率或预测分值。具体题号与分年结果见[样本记录](../../verification/核心考点精要-考频样本.md)，覆盖边界见[覆盖表](11-大纲与教材考点覆盖表.md)。

## 五分钟速记

- 机密性防泄露，完整性防未授权改变，可用性关注服务；认证回答是谁，授权回答能做什么。
- 对称加密适合批量数据；公钥机制用于密钥协商／封装、签名等不同任务；哈希不是可逆加密。
- 数字签名使用签名者私钥生成、相应公钥验证；保密通信不能仅靠签名。
- BLP 保机密：不上读、不下写；严格 Biba 保完整：不下读、不上写。
- 备份不能自动保证可用，复制不能代替离线或历史备份；恢复必须演练。

## 1 密码、签名与 PKI

| 技术 | 目的与要点 | 易混点 |
|---|---|---|
| 对称加密 | 通信双方使用共享秘密密钥，适合大数据量 | 需安全分发与管理密钥 |
| 非对称密码 | 公钥与私钥配合，支持不同密码学任务 | 不应把所有签名都解释成“私钥加密” |
| 哈希 | 将输入映射为摘要，用于校验等 | 无密钥哈希不能独自证明发送者身份 |
| MAC／HMAC | 使用共享密钥认证消息 | 持有同一密钥者都能生成，不能直接提供签名式第三方证明 |
| 数字签名 | 绑定签名者密钥与消息，支持完整性、来源验证 | 不自动保护消息机密性 |
| 数字证书 | 将身份与公钥等绑定，由可信签发链验证 | 需验证有效期、用途、信任链及撤销状态等 |

数字信封的理解：用随机对称密钥加密正文，再用接收方公钥机制保护该密钥；接收方使用私钥恢复密钥后解密正文。签名与保密可以组合，但职责不同。

PKI 中 CA 负责签发证书，RA 可负责登记和身份核验，证书库保存证书等信息。不能把拿到证书等同于证书必然可信。

工程补充：AES 的分组长度为 128 位，密钥长度与分组长度不同；多分组数据需选择合适工作模式。采用认证加密时还要正确管理 nonce／IV 和认证标签，不能只说“分块分别加密”；简单重复模式可能泄露结构。实际方案使用成熟密码库与明确协议，教材算法知识不能代替安全实现评审。

## 2 访问控制与安全模型

| 模型 | 关注点 |
|---|---|
| DAC | 由对象所有者等自主决定授权 |
| MAC | 根据系统强制策略及安全标签控制 |
| RBAC | 用户获得角色，角色关联权限 |
| ABAC（工程补充） | 根据主体、资源、动作及环境属性决策 |
| BLP | 分级机密性，限制敏感信息向低级流动 |
| Biba | 完整性，限制低可信数据污染高可信对象 |
| Clark-Wilson | 受控事务、职责分离、完整性验证和审计 |
| Chinese Wall | 根据访问历史防止利益冲突 |

BLP 的“上／下”指机密级别，Biba 指完整性级别，不能把这两种级别混成同一量纲。规则有不同变体，题目指定强星属性等时按题设。

最小权限限制授权范围，职责分离避免单人独占关键操作，审计记录谁在何时对什么做了什么及结果。认证成功不意味着对任意对象都有访问权限。

## 3 常见威胁与防护匹配

| 问题 | 主要防护思路 |
|---|---|
| SQL 注入 | 参数化查询、输入约束、数据库最小权限 |
| XSS | 按输出上下文编码、限制不可信脚本执行 |
| CSRF | 请求来源验证、令牌等机制，结合 Cookie 策略 |
| 越权 | 服务端逐请求检查资源归属与操作权限 |
| 重放 | nonce、时间窗口、序列号及状态校验 |
| 拒绝服务 | 容量规划、限流、隔离和上游防护 |
| 数据泄露 | 分级授权、传输与存储保护、脱敏及审计 |

防火墙控制网络边界流量，IDS 检测与告警，IPS 可在线阻断；它们不能替代应用授权与安全编码。TLS 保护传输链路，不自动保护终端、数据库或应用逻辑。

WPDRRC 的六环节：预警、保护、检测、响应、恢复、反击；三个要素：人员、策略、技术。考试记体系与职责，不能把“有防火墙”当作完整安全体系。

## 4 可靠性、可用性与恢复

故障导致服务偏离要求；可靠性度量依赖规定时间、条件和运行剖面。软件通常不存在与机械磨损完全相同的失效机制，修改还可能引入新缺陷。

| 概念 | 理解 |
|---|---|
| MTTF | 平均失效前工作时间，注意题目是否讨论可修复系统 |
| MTTR | 平均修复时间 |
| 可用度 | 以平均运行时间／平均完整运行修复周期近似时，为 MTTF/(MTTF+MTTR) |
| RTO | 故障后希望在多长时间内恢复服务 |
| RPO | 希望可接受的数据回退时间范围 |

有的资料用 MTBF 表示平均正常工作间隔，有的把修复计入周期；公式应先统一定义，不能机械替换字母。

自编例：每个平均周期正常工作 99 小时、修复 1 小时，可用度为 99/(99+1)=99%。缩短修复时间可提高可用度，即使故障发生次数没有减少。

## 5 可靠性计算与容错

下列为基础模型的教学归纳，必须检查“独立失效、理想切换”等前提：

- 串联系统所有部件都成功才成功：$R_s=\prod_i R_i$。
- 并联系统至少一个部件成功就成功：$R_p=1-\prod_i(1-R_i)$。
- 常失效率指数模型：$R(t)=e^{-\lambda t}$，$MTTF=1/\lambda$。
- 若 F(t) 表示累计失效分布，则 $R(t)=1-F(t)$，F(t) 非递减；失效率 λ(t) 与 F(t) 不是同一个量。

自编例：两个独立部件可靠度都是 0.9，串联为 0.81，理想并联为 0.99。若共享电源或存在共同软件缺陷，就不能直接认为独立，实际冗余收益可能较低。

N 版本程序用多种独立实现及表决降低单一设计缺陷影响；恢复块通过验收测试选择替代实现；检查点／回滚恢复保存状态后恢复；冗余与恢复都需要验证覆盖率和失败路径。

可靠性测试依赖代表实际使用的运行剖面；不能只测最容易通过的输入。狭义可靠性测试侧重取得数据评估指标，广义过程还涉及发现薄弱环节并改进。

## 6 案例表达

自编任务：系统要求故障后较快恢复且不能丢失关键提交。答案应分别写服务故障检测与切换、数据持久化与复制确认、备份恢复与演练，给出 RTO/RPO 并解释成本。不能只说“增加一台服务器”。

对安全题按“资产与威胁—身份与权限—传输和存储—审计与恢复”组织；每项措施对应一个具体风险，并说明业务可用性与性能代价。

## 自编自测与参考答案

1. 签名能让所有观察者看不到正文吗？——不能，机密性需要加密等机制。
2. SHA 摘要相同验证成功就确认发送者身份吗？——不能；须结合可信认证机制。
3. BLP 为何禁止向低级对象写？——防止敏感信息向低机密级流动。
4. RPO=5 分钟等于五分钟恢复服务吗？——不是，前者约束数据回退，后者属于 RTO。
5. 两个独立部件可靠度 0.8、0.9，串联及理想并联为多少？——0.72、0.98。
6. F(t) 可以随时间增加而减少吗？——若它是累计失效分布，不可以；不要与失效率曲线混淆。
7. 样本练习：2025 上综合 31、68，下综合 24–25、33–34，下半年案例一问题 3（安全子主题）。

完成标准：能分清认证、授权、加密与签名，能解释恢复目标，并带前提使用可靠性公式。

## 补强：可靠性模型、测试与评价

软件缺陷通常来自设计实现，不具有硬件材料磨损的同样机制；运行剖面变化、环境变化和代码修改仍会改变失效表现。不能据“软件不磨损”推出软件一定不会失效，也不能说所有硬件失效前都有警告。

教材把模型大致分为十类：种子法、失效率类、曲线拟合类、可靠性增长、程序结构分析、输入域分类、执行路径分析、非齐次泊松过程、马尔可夫过程、贝叶斯分析。重点理解其依据：种子法以注入与检出比例估计残留缺陷；增长模型描述排错过程；结构或路径模型考虑组成与执行；输入域模型依赖使用概率；马尔可夫描述状态转移；贝叶斯结合先验与观测。模型类别可能交叉，不是十个完全互斥的产品。

模型包含假设、度量、参数估计及数据要求。选择时检查假设适用性、预测能力、输出是否满足目标、数据是否可收集及使用成本。失效次数、失效间隔与缺陷数不是同一个指标；排错可能引入新缺陷，不能默认完全排错。

运行剖面给出使用场景及其发生概率，据此设计有代表性的可靠性测试。增长测试用于发现问题并改进；验证测试检查是否达到规定目标；摸底测试了解现状。管理贯穿需求目标与验收准则、设计容错、实现约束、测试记录及运行反馈。

评价流程：选模型→定义并收集可靠性数据→估计参数和检验拟合→评估当前水平并预测→结合限制作决策。零失效观测不等于可靠度为 1；工程上可以在明确统计假设和置信水平下估计界限，不能凭“没见过故障”宣布绝对可靠。

## 补强：容错、安全风险与脆弱性

N 版本程序设计以不同实现并行求解并进行结果表决；恢复块以主块、验收测试、状态恢复和备选块顺序尝试。前者要考虑共同规格缺陷和表决器故障，后者要考虑验收测试质量与重试时延；多版本相似度高可能产生共因失效，不能直接当作独立部件相乘。

故障树 FTA 从顶层失效向原因作演绎分析；FMEA 从部件或功能的失效模式向影响作归纳分析。教学辨析：一个顶事件有任一原因就触发用或关系，要求多个条件共同成立才触发用与关系；具体连线由题干决定，不能猜图。

安全风险联系资产、威胁、脆弱性、发生可能性和影响；风险处置可规避、降低、转移或接受，并持续复评。安全体系同时包括技术、组织和管理，不能等同于采购防火墙。数据库完整性涉及实体、参照和业务约束；安全性涉及授权、审计、加密和备份保护，两个概念关联但不等价。

脆弱性分析先划定资产与信任边界，再检查入口、权限、数据流与依赖，评估影响并修复复验。分层关注越层访问与暴露接口，事件系统关注消息伪造及重放，微服务关注调用身份与服务权限，微内核关注插件隔离。不能把一种架构风格直接判定为“安全”或“不安全”。

访问控制矩阵按主体与客体表达权限；ACL 从客体列出允许访问者；能力表从主体列出可访问对象。任务控制与工作流状态相关；角色控制围绕岗位职责，属性控制综合主体、资源、环境等属性。教学自测：同一角色在审批前后权限变化，应说明流程状态与授权条件，而不只回答“使用 RBAC”。

题设若明确采用旧版五级安全保护分类，按该版本辨认自主、审计、标记、结构化、访问验证等术语；不要将历史教材分类与现行测评实施规则无条件等同。网络安全服务按身份鉴别、访问控制、机密性、完整性和抗抵赖等目标分析，具体协议的能力与配置有关。

## 补强：可靠性目标与扫描辨析

可靠性目标应先明确运行条件、时间与功能，再结合失效严重程度规定可靠度、失效强度或平均失效前时间等指标。严重程度可按成本损失或能力受损划分，同样的故障在不同系统里严重程度可能不同；教材中的金额分级是示例，不是所有系统通用阈值。

广义可靠性测试包含目标、剖面、建模、试验、数据分析与评价等活动；狭义可靠性测试主要是在预期使用环境中，按既定测试用例执行以获取可靠性数据。二者关系是范围不同，不能把广义测试仅理解为运行更多用例。

防御性识别：全 TCP 连接扫描尝试建立完整连接；SYN 扫描基于部分握手响应判断端口状态；FIN 扫描利用特定报文响应差异推测状态，但受协议栈与防护配置影响；代理扫描借助中间代理观察目标响应。扫描结果不等于已证实漏洞，应结合授权范围、资产信息和复核处理，不将探测误报直接当作失陷事实。

## 教材案例提要：安全架构

教材 RADIUS 案例通过协议逻辑、业务逻辑与数据逻辑分层，分离通信处理、认证授权计费与数据访问。AAA 中 Authentication 验证身份，Authorization 决定可用服务，Accounting 记录资源使用和计费/审计信息；不能把三个 A 都理解成登录验证。

工业混合云案例关注跨区域协作与内部数据保护：先区分哪些数据和工作负载可放公有云、哪些保留在受控环境，再处理身份、连接、安全边界与数据迁移。混合云不因同时拥有两种云就自动更安全，必须评估各连接和权限配置。

自测：统一身份认证后能否省略资源权限检查？答案：不能，身份认证与授权分别承担不同目标。原书具体逻辑和配置回查教材案例。

## 补强：安全组织与网络防御辨析

安全组织的机构设置分决策层、管理层、执行层：分别侧重确定目标与资源、组织制度和协调监督、落实操作与控制。岗位定义职责，人事管理覆盖在职、待职及离职人员的教育、考核与监管。不能把技术产品清单当作组织保障体系。

| 考点 | 机制与防御思路 | 易错点 |
|---|---|---|
| ARP 欺骗 | 错误的 IP—MAC 映射使局域网流量发往错误位置；关键映射绑定及异常检查可辅助防护 | 绑定有维护成本，地址变化需要管理 |
| DNS 欺骗 | 伪造或污染解析结果；检查解析配置及请求应答异常，并核对可信来源 | 域名指向被改变不等于原网站主机已被入侵 |
| IP 欺骗 | 伪造源地址；检查来源合理性，避免仅凭地址授予信任 | TCP 三次握手不等于业务身份认证 |
| TCP/IP 堆栈加固 | 关注协议处理漏洞、异常流量与连接资源耗尽；修补漏洞并限制资源滥用 | 旧版系统注册表参数不应直接当成通用配置 |
| ICMP | 支持差错报告和诊断，也可能被滥用；按业务需要过滤异常流量 | 正常诊断消息与恶意流量需要区分 |
| SNMP | 承载设备监测及管理；约束管理访问与权限，关闭无用管理服务 | 管理接口暴露会影响设备控制安全 |
| 网络漏洞扫描 | 从网络侧观察目标暴露的服务与漏洞迹象 | 扫描可达范围不等于主机全部内部状态 |
| 主机漏洞扫描 | 利用目标内部访问能力检查文件、进程和配置，常借助代理 | 覆盖更深也带来部署、权限与维护要求 |

自测：端口开放能否证明存在可利用漏洞？答案：不能。扫描结果要结合服务版本、配置及适用条件核实，修复后再验证。教材中的历史操作系统命令和产品描述应放回其版本语境理解。

## 补强：国家信息安全管理的教材语境

教材 4.2 以 2014 年成立中央网络安全与信息化领导小组为历史例子，说明国家层面统筹信息化发展与信息安全保障的作用。复习抓住三点：网络安全关系国家安全与发展；管理需要总体布局与跨部门协调；技术保障须与组织和制度配合。

这是对教材历史段落的提要，不能把历史机构名称当作现行机构名录。此处尚未逐一列出现行机构职能、部门分工及具体管理要求；遇到明确指定时间或制度版本的题目，应按题设回查。
