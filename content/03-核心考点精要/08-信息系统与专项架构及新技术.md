# 信息系统与专项架构及新技术

本篇为 AI 辅助整理的非官方学习手册。概念采用教材归纳与明确标出的工程补充；口诀、例题、答案及作答模板均为教学归纳，不是官方答案或真实项目事实。优先级是学习安排，样本考频不代表未来命题概率。

## 范围与优先级

优先级 P1。2023 年起仓库五场考试的主主题统计：综合知识 30 题、案例 7 道大题、论文 1 题。每题只归一个主主题；组内粒度不同，计数不代表单考点概率或预测分值。具体题号与分年结果见[样本记录](../../verification/核心考点精要-考频样本.md)，覆盖边界见[覆盖表](11-大纲与教材考点覆盖表.md)。

## 信息系统：按服务对象区分

| 系统 | 解决的问题 | 识别线索 |
|---|---|---|
| TPS 业务处理 | 记录日常交易并保证处理正确 | 订单、入库、结算 |
| MIS 管理信息 | 汇总业务数据支持常规管理 | 报表、统计、例行管理 |
| DSS 决策支持 | 数据与模型辅助半结构化决策 | 方案比较、模拟、预测 |
| ES 专家系统 | 用知识和推理支持专业判断 | 知识库、推理机、解释机制 |
| OAS 办公自动化 | 支持办公协作 | 文档、流程、通信 |
| ERP 企业资源规划 | 集成企业资源与业务流程 | 财务、生产、采购、库存协同 |

教学记忆：TPS 记业务，MIS 看管理，DSS 比方案，ES 用知识。它们可以集成，不能仅凭“含有报表”就认定整个系统是 MIS。

MRP 根据主生产计划、物料清单和库存信息展开物料需求；MRP II 扩展到制造资源与管理闭环；ERP 进一步面向企业资源集成。BOM 描述产品的物料组成，不是采购订单。

## 信息化规划与企业架构

| 方法 | 核心抓手 | 易混点 |
|---|---|---|
| CSF 关键成功因素法 | 从目标识别关键因素及所需信息 | 强调重点，不等于穷举所有需求 |
| SST 战略目标集转化法 | 将组织战略目标转成信息系统目标 | 关注目标转换和相关人员诉求 |
| BSP 企业系统规划法 | 分析业务过程与数据类，规划系统结构 | 自上而下规划、自下而上实施 |

企业架构要让业务、数据、应用和技术相互对齐。TOGAF 的 ADM 按教材归纳为：预备阶段；A 架构愿景；B 业务架构；C 信息系统架构（数据与应用）；D 技术架构；E 机会与解决方案；F 迁移规划；G 实施治理；H 架构变更管理。需求管理贯穿各阶段，不是最后才做的一步。

作答时写“现状—目标—差距—迁移与治理”，不要把采购设备当作完整信息化规划。

## 嵌入式与实时系统

实时性强调在截止时间内完成响应，不能用平均运行速度替代最坏响应时间分析。硬实时任务错过截止时间可能造成不可接受后果；软实时系统允许一定程度的超期并付出服务质量代价。

| 概念 | 核心机制 | 应说明的条件 |
|---|---|---|
| 中断 | 外部或内部事件触发处理 | 中断响应、优先级、嵌套与处理时间 |
| DMA | 控制器协助设备与内存传输 | CPU 仍需配置和处理完成通知 |
| 看门狗 | 未按时喂狗触发恢复 | 不能代替故障定位或保证业务状态正确 |
| 优先级反转 | 高优先级任务等待低优先级任务持有的资源 | 优先级继承或天花板协议可缓解 |
| DARTS | 分解并发任务并定义任务接口 | 必须考虑同步、通信和时间约束 |

工程补充：单处理器上，满足独立、可抢占、周期任务且截止期等于周期等假设时，EDF 按最近截止期动态排序；RM 按周期长短分配固定优先级。不能把这些理想模型的结论直接用于包含阻塞和调度开销的实际系统。

教学示例：设备每 20 ms 采样一次，单次处理最坏耗时 3 ms。该任务利用率为 3/20=15%。这只是一项任务的占用率，不能据此断言包含其他任务的系统可调度。

## 专项架构辨析

| 领域 | 应优先分析 | 常见误区 |
|---|---|---|
| 通信系统 | 协议、带宽、时延、可靠传输与管理 | 只画业务服务，不说明通信约束 |
| SDN | 控制平面与数据转发平面分离，控制逻辑可编程 | 逻辑集中不等于只能部署一台控制器 |
| DAS | 存储设备直接连接主机 | 不等于网络文件共享 |
| NAS | 通过网络提供文件访问 | 与 SAN 的块访问区分 |
| SAN | 存储网络提供块级访问 | 不等于必须使用某一种物理链路 |
| 边缘计算 | 就近处理、低时延、带宽和隐私约束 | 不能假定边缘节点永远在线或资源无限 |
| CPS | 计算、网络与物理过程耦合及反馈控制 | 不只是物理设备的静态展示 |
| 数字孪生 | 数字模型与实体状态映射、更新与分析 | 不等于仅制作三维模型 |

## 人工智能、知识图谱与区块链

教材知识归纳：人工智能系统需区分知识表示、学习、推理和决策。监督学习依赖带标签样本；无监督学习发掘未标注数据结构；强化学习围绕状态、动作、奖励和策略进行交互学习。准确率不能代替所有评价指标，类别不均衡时尤其要看精确率和召回率。

知识图谱用实体、关系及属性表达知识；典型流程包括抽取、消歧与融合、存储、查询及推理。图数据库是一种存储与查询技术，知识图谱是知识组织方式，二者不能画等号。

工程补充：端侧 AI 要权衡模型效果、内存、功耗和推理时延；量化降低数值精度，剪枝移除部分连接或结构，知识蒸馏让学生模型学习教师行为。优化后要重新测量效果，不能声称压缩必然无损。

区块链通过密码学链接、分布式复制与共识等机制维护记录。哈希用于完整性关联；签名用于验证来源与完整性；共识决定各节点认可的记录顺序或状态。链上记录并不能自动证明链下输入真实，智能合约也不自动消除程序缺陷。

## 案例作答方法

按“领域约束—架构分工—数据流—失效处理—验证指标”组织答案。例如边缘设备断网：先说明本地哪些功能继续运行，再写持久化缓冲、恢复后的重传与去重、容量耗尽策略，最后给出离线时长和恢复验证方案。

不要用一组新技术名词替代问题分析；明确哪些环节需要集中治理，哪些需要本地自治。

## 闭卷自测与教学参考答案

1. ERP 与 MRP 的范围有什么区别？
2. ADM 的 C 阶段包括什么？需求管理发生在哪个阶段？
3. 为什么平均响应时间不能证明硬实时任务达标？
4. 知识图谱与图数据库是否同义？
5. 数据上链是否证明其源头真实？
6. 边缘节点断网后补传，为什么还需要幂等处理？

参考答案：1. MRP 重点是物料需求，ERP 面向企业资源和流程集成。2. 数据与应用架构；需求管理贯穿过程。3. 截止时间约束需要考虑最坏情况。4. 否，分别是知识组织与存储查询技术。5. 否，仍需保证采集与输入可信。6. 超时重试可能重复发送，同一业务记录不能重复生效。

## 补强：信息系统发展与系统计划

教材归纳：信息系统的基本功能是输入、存储、处理、输出和控制；生命周期分产生、开发、运行、消亡。诺兰阶段模型依次为初始、传播、控制、集成、数据管理、成熟，用于理解信息化发展阶段，不是每个企业都必然按相同速度推进的规律。

TPS 关注业务数据输入、处理、数据库维护、报表和查询；MIS 组织信息源、处理器、用户与管理者；DSS 将数据与模型结合，知识型结构还加入知识支持；ES 由知识库、综合数据库、推理机、知识获取、解释程序和人机接口协作。不能把 DSS 的模型库与 ES 的知识库混为一谈。

WMS 管仓储业务，MES 管制造执行，PDM 管产品数据，CRM 管客户关系；ERP 通过共同数据和流程连接资源管理。电子政务辨认政府内部及政府与其他主体的服务协作；电子商务辨认交易主体、交易信息和履约过程，不能仅以“有网站”判断已经完成业务集成。

系统计划先提出问题与目标，再做技术、经济、运行组织及合规等可行性分析；比较新旧系统的成本、收益、风险与资源可复用程度；制定实施、迁移、验证和退役方案。可行不等于最优，要说明评价标准及备选方案的取舍。

## 补强：边云协同、机器人与安全关键系统

| 边云协同类型 | 教学解释 |
|---|---|
| 资源协同 | 按时延、算力和成本分配云边资源 |
| 数据协同 | 边侧过滤聚合、云侧全局分析，处理同步与权限 |
| 智能协同 | 云侧训练或统筹、边侧推理与反馈，按实际分工调整 |
| 应用管理协同 | 统一分发、版本、部署和回滚 |
| 业务管理协同 | 将局部业务动作与全局流程协调 |
| 服务协同 | 云边服务互相发现、调用和组合 |

自编情境：边缘摄像节点断网仍需完成本地判断，云端恢复后接收结果与诊断数据。答案应说明模型版本、缓存容量、重传去重和时间戳，不能只写“使用边缘计算”。

机器人系统需要感知、决策规划与执行控制等能力；ROS 提供构建机器人软件的工具与通信等支持，不宜把它理解为替代所有底层实时内核。对应 2024 下案例的接口辨析：Topic 表达持续发布订阅数据流；Service 表达一次请求与响应；Action 表达长任务、进度反馈和结果；Parameter 表达节点配置。具体版本、中间件和产品差异仍需回查，不能声称所有 ROS 2 部署都具有同样的实时与安全保证。

嵌入式数据库可按内存、文件与网络组织方式辨认，选型关注资源、存储持久性、实时约束与恢复；嵌入式中间件负责屏蔽差异和协同通信。DDS 侧重以数据为中心的发布订阅和服务质量，CORBA 侧重分布式对象调用；车载 SOME/IP 题应区分服务接口、服务发现、请求应答及事件通知，不能因同时用于通信就视为同一协议。

安全关键系统分析从危险识别、风险分析、危险原因分析到风险降低与安全需求形成。Safety 关注避免系统失效造成伤害，Security 关注防止未经授权的访问和破坏；可靠性高不自动证明安全。形式化验证检查模型性质，测试验证具体执行行为，需要组合使用并说明覆盖边界。

物联网三层可按感知、网络传输、应用区分；数字孪生强调实体、数据模型和同步反馈；CPS 强调计算通信与物理过程闭环。VR 构造虚拟体验，AR 将信息叠加到现实感知，不能仅按是否戴头显区分。

自编自测：持续输出传感器数据与带进度反馈的导航任务分别使用哪类接口？教学答案：Topic 与 Action。选择嵌入式数据存储时为什么还要考虑断电？答案：内存中的正确结果不等于已持久化，需分析提交、介质与恢复。

## 补强：MIS 功能结构与办公系统

MIS 的功能结构按管理职责组织，功能过程结构进一步表达各职能通过哪些相关活动完成。功能/层次矩阵将管理功能与战略计划、管理控制、运行控制等层次交叉组织，不能把功能分类误当硬件分层。教材列举销售市场、生产、后勤、人事、财务和会计、信息处理、高层管理七个子系统；这是组织方式的例子，具体机构可有不同划分。

办公自动化系统由计算机设备、办公设备与软件系统共同组成，支持事务处理、信息管理和辅助决策。设备联网是基础，文档、通信与流程协同才把设备能力转为办公业务；不能把 OAS 等同于某一个文字处理软件。

## 教材案例提要：企业架构与嵌入式

以下按教材案例归纳，不把其中历史产品描述当作当前版本承诺，不复原缺少依据的原图。

| 教材案例 | 核心机制 | 复习重点 |
|---|---|---|
| 价值驱动的体系结构 | 结合价值期望、环境反作用力与变革催化剂识别架构挑战 | 相同功能在不同情境中效用和约束不同，方案要有优先级 |
| HL7 的 Web 服务应用 | 以参考信息模型、消息结构、交互与应用角色组织语义，通过服务基础设施交换 | 传输连通不等于医疗数据语义一致；这里只说明教材中的 HL7 V3 语境 |
| 航空企业服务整合 | 既有主机、开放系统与点对点集成导致协作成本；从业务分析、服务建模到架构设计推进整合 | 复用既有资产同时降低硬编码耦合，而非把旧系统全部重写 |
| 教材中的鸿蒙架构 | 内核、系统服务、框架、应用分层，按设备需求裁剪；提供跨终端协作能力 | 区分层次与职责，不能直接推断所有当前版本采用相同内核结构 |
| GENESYS | 通过消息与接口抽象、分区隔离处理复杂性与健壮性 | 构件可替换仍需接口契约、故障隔离和时间条件 |
| 物联网操作系统 | 连接资源受限的设备、通信能力和应用服务 | 结合硬件资源、实时性、网络与安全约束选取系统能力 |

自测：跨系统互联后为什么还要做语义建模？答案：字段、事件、角色和业务状态的含义可能不一致，消息送达不代表接收方正确理解。

## 补强：专家系统六项特点

教材把专家系统的特点归纳为：超越时间限制、操作成本低廉、易于传递与复制、处理手段一致、善于克服难题、适用特定领域。理解时分别对应持续提供已编码知识、复用知识降低重复服务成本、复制知识与程序、按既定规则推理、利用专业知识求解以及领域边界。

这些是能力与应用特点，不能推成“任何系统都便宜、永不出错、能代替所有专家”。知识获取、维护与验证仍有成本；知识过时、规则冲突或输入超出领域都会影响结果。自测：专家系统是否天然适合解决所有通用问题？答案：否，其知识和推理策略受特定领域约束。
