# verification —— 核查记录旁路目录

本目录存放大纲、教材清洗稿与扫描件一致性方面的核查记录，与正文物理隔离。唯一标准是**忠于扫描件图像**；不扩展判断原书内容的正确性、时效性或其他事实。

## 为什么要隔离

清洗稿正文只放正文。图题、共用题干、作答规则、题量声明属于正文的一部分；
证据、出处、裁决、可信度评级、待复核标记一律不进正文，只写在本目录。

这样做的原因是：正文一旦混入核查语言，读者无法区分"原书这么写"和"整理者这么认为"，
而且核查语言会随时间失效，却没人清理。

## 三层分工

| 环节 | 判断依据 | 产物 | 不产出 |
|---|---|---|---|
| 清洗 | 忠于原文 | 正文 Markdown | 注记、评价、示意图 |
| 校验 | 机器可判定（编码、换行、结构、计数、索引一致） | 脚本退出码 | 任何文件内容 |
| 核查 | 清洗稿是否忠于扫描件图像 | 本目录下的记录 | 正文里的任何一个字 |

## 使用约束

1. **本目录不纳入内容门禁。** `scripts/validate_knowledge_base.py` 对这里只做编码与换行检查，
   不检查内容、不要求覆盖率、不要求任何文件必须存在。
2. **不要求全覆盖。** "没有记录"等于"没核查过"，这是合法的默认状态，不是待办缺口。
3. 大纲与教材核查必须只以 PDF 页面图像为证据；不得使用 OCR 或 PDF 文本层。具体流程见下文。
4. 能由图像确认的修正直接改正文；核查报告留在本目录，记录来源哈希、正文版本、实际范围和独立验证结果。报告只证明其明确覆盖的片段，不代表全章或全书已核查。
5. 不要求全覆盖，不设覆盖率或通过率目标；未记载的内容保持“未核查”。图像不足以判断时标“无法判定”，不得推测补全。

第 1、2 条是硬约束：一旦把"记录是否齐全"变成机器可检查的指标，
自动化工具就会为了满足指标而生产内容——本仓库此前 325 个凭空生成的示意图即由此而来。

## 大纲与教材扫描件事实核查流程

### 目的与唯一标准

本流程用于核查 `content/` 中大纲和教材清洗稿是否忠于对应扫描件。**判断标准只有清洗稿与扫描件图像是否一致**；不评判原书知识是否正确、是否过时、是否符合现行政策或其他外部标准。

PDF 页面渲染图像是唯一证据。核查过程不得使用 OCR、PDF 文本层抽取、搜索索引或其他自动识字结果。其他 AI 的判断是待复核意见，不构成独立证据；扫描图像不能支持结论时，记录“无法判定”，不猜测。

### 核查前固定对象

每一轮核查限定一个明确范围，例如一个前言、一章或一个小节。开始前记录：

- 清洗稿路径及其 Git 提交；
- 使用的 PDF 文件名、SHA-256、页数；
- 本轮核查范围；
- PDF 物理页范围。若清洗稿源自另一版扫描件，不得假定页码一一对应；只在页面内容足以确认对应关系时记录映射。

如果 PDF 身份不能与登记校验值对应，或找不到可确认的原文页面，暂停该范围的事实判断并记录限制。

### 第一遍：逐项比对

1. 将 PDF 页面渲染为图像。可调整渲染分辨率、放大或临时裁切页面；不得对图像运行 OCR。
2. **先只看图像，把该页的标题与条目逐条记下来，再打开清洗稿比对差异。** 顺序反过来会退化成"看一眼觉得差不多"的确认偏误：大纲正文是密集的术语清单（如"CPU、GPU、DSP、FPGA"），先读清洗稿再看图时，漏掉一个缩写、调换两项顺序、把"预计"看成"评估"都不会被察觉。假的"相符"比没有记录更糟——它把"未知"写成了"已确认"，而且不会有人再查第二遍。
3. 阅读限定范围内的清洗稿，逐段与对应页面图像比对。检查文字是否遗漏、增加、替换或调序，以及标题、列表、表格等结构是否改变原文关系。
4. 只把需要保留的内容与扫描图像比对。按仓库清洗规范排除页码、页眉页脚等明确的版面噪声；不得以“更正确”“更通顺”或领域常识为由改写正文。
5. 每项判断记录清洗稿定位、扫描 PDF 物理页及图像区域、比对结果和必要说明。不要在记录中复制大段第三方原文。
6. 用以下结果之一标记每项：
   - **相符**：图像清晰，清洗稿内容与图像一致；
   - **有差异**：图像清晰，能指出具体遗漏、增补、替换、调序或结构偏差；
   - **无法判定**：图像模糊、裁切、版本对应或上下文不足，不能可靠判断。

“相符”只覆盖记录中明确核对的范围，不代表整章或整本书已核查。

### 分批推进

一次核查不要超过 5–8 页。超出这个量后半段的判断质量会下滑，而下滑本身不可观测——记录上看不出哪几页是认真核的、哪几页是扫过去的。每轮结束立即写记录，并在记录中写死本轮覆盖的物理页范围。宁可分十轮，不要合成一轮。


### 第二遍：独立验证第一遍

1. 将同一批清洗稿范围和相同 PDF 页面图像交给另一位 AI 独立核查；不提供第一遍结论、差异列表或期望答案，避免锚定。
2. 独立核查者仍以图像为唯一证据，不使用 OCR 或 PDF 文本层，并按同一结果标签独立记录页码、区域和差异。
3. 再由验证者对照两份记录及原始图像，逐项检查：第一遍声称“相符”的范围是否真的覆盖并匹配；“有差异”是否可从图像直接观察；是否遗漏明显差异；页码与定位是否可重现。
4. 两遍不一致时，不以多数票裁定。回到同一页面图像复查；仍无法解决则将该项定为“无法判定”，并写明分歧点。
5. 验证者输出“核查记录通过 / 需修正 / 无法验证”及逐项理由。不能只给总体通过结论。

第二遍是对核查过程与判断的独立检查，不是新的事实来源。多个 AI 一致也不能弥补图像证据不足。

### 修订与记录

- 仅对“有差异”且图像证据可定位的内容做最小修订；修订不得超出图像支持范围。
- 修订后重新核对受影响片段，并让独立验证者只针对该片段复核。
- “无法判定”不改写成确定内容；必要时保留正文现状并记录无法判断的原因。
- 每轮保留一份简短核查报告，足以让其他人使用相同 PDF、页码和清洗稿提交复核。报告应包含来源 SHA-256、正文提交/范围、核查与独立验证结果、未决项；不宣称未检查的范围已核查。
- 不设全库覆盖率、通过率或清零目标；未被报告覆盖的内容仍是未核查状态。

### 记录格式

按需在核查报告中使用下表；只记录实际检查过的内容：

| 清洗稿定位 | PDF 物理页/图像区域 | 结果 | 观察或差异 | 独立验证 |
|---|---|---|---|---|
| 文件路径、标题或段落 | 页码；能定位时注明区域 | 相符 / 有差异 / 无法判定 | 简述，不抄录大段原文 | 相符 / 有差异 / 无法判定，并注明分歧 |

### 给核查 AI 的任务说明

> 只核查所给清洗稿范围是否忠于所给 PDF 页面图像。PDF 页面图像是唯一证据；禁止 OCR、PDF 文本层抽取及外部知识。逐项给出清洗稿定位、PDF 物理页/区域及“相符 / 有差异 / 无法判定”。不要把原书内容是否正确、是否过时或是否符合现行规则纳入判断；不要猜测模糊文字，不要把未检查范围称为已核查。

> 若你是独立验证者，不查看第一遍结论后先独立核对；之后再逐项检查第一遍定位、结论及范围覆盖。分歧回到图像复查，不能解决就标“无法判定”，不得投票裁定。
